# Проверка archive-month-from-ift-bot

Реализовано в feature/manage-categories на основе принятого v2-кода. ПРОМ-контейнер, рабочая книга, установленный production Apps Script и main не изменялись этим change. Предшествующие незакоммиченные документы production-переноса и экспериментальный native_restore не включаются в выпуск.

## Проверено локально

- Python: 245 тестов прошли. В число входят существующие локальные тесты не включаемого в этот change native_restore; CI проверит точный состав feature-коммита.
- Node: test_apps_script.cjs, test_archive_web.cjs (включает test_archive_script.cjs), test_reactivation_script.cjs прошли.
- Общее ядро ручного и web-архиватора: прежние суммы/колонки/снимки, подтверждения/отказы, восемь нативно перенаправленных диаграмм, все 12 переходов месяца и неизменность D2 в обычном месяце.
- Web без getUi/getActiveSpreadsheet/document lock: HMAC/owner/scope/срок запроса, отказ до открытия книги; отдельные save/clear, отказ от очистки, новая трата перед clear, повтор старого ID после появления новых операций следующего месяца; восстановление того же этапа после очистки/перед публикацией результата без повторного переключения месяца.
- Асинхронный HTTP-клиент: подпись точных байтов, GET redirect только на ожидаемый Google-host без передачи подписи/тела, отказ при чужом request_id и несовместимом протоколе, timeout после clear приводит только к status. Журнал 0600 сохраняет тот же ID после создания нового клиента.
- Telegram dispatcher: два подтверждения, явная замена архива, keep без clear, /help со сворачиваемой клавиатурой, выход из ввода примечания в архивацию, чужие/group callbacks без вызова клиента, отсутствие кнопки/команды при выключенной функции.
- Приватная ИФТ-конфигурация сохраняется prepare_test_env.py при передеплое и не наследуется из production. Неверные URL/ключ и включение на production-книге отклоняются. Проверка endpoint в release_check выполняется до замены тестового контейнера без архивации.

## Ожидается от владельца

По инструкции docs/ift-bot-month-archive.md установить data/macros.gs только в ИФТ bound-проект, добавить свойства из локального приватного secrets/ift-month-archive/script-properties.json и развернуть web app от владельца с доступом для HTTP-вызова. Ключ не публиковать. Для подключения нужен только URL /exec.

После получения URL оператор проведёт аутентифицированный status, добавит настройки только в приватный test env и выполнит существующий Test stand release. До этого задача 3.2 не завершена, новый test-тег не публиковался, новая кнопка в работающем боте не обещана. Живые архивация/очистка не выполнялись. Задача 3.3 остаётся открытой до ручной ИФТ-приёмки владельцем.

Приёмка production-архивации в конце месяца из promote-v2-to-production остаётся открытой.
