# Предварительная проверка категорий

Реализованы проверка на чтение, подготовка плана, применение к локальной копии, восстановление и установка в явно выбранную Google-копию. Автоматические проверки выполнены на искусственных данных; настоящая Google-копия и установленный Apps Script пока требуют ручной приёмки. Рабочая книга и серверный бот не изменялись.

Из корня проекта с установленными зависимостями:

```sh
python -m finance_bot.category_migration --xlsx /path/to/PnL.xlsx --report /tmp/category-preflight.json
```

Для актуальной Google Sheets можно явно передать ID таблицы и путь к локальному ключу (не содержимое ключа):

```sh
python -m finance_bot.category_migration --spreadsheet-id SPREADSHEET_ID --credentials /path/to/service-account.json --report /tmp/category-preflight.json
```

Google-клиент использует scope `spreadsheets.readonly`. Инструмент вызывает только чтение листов и метаданных. В XLSX ничего не пересчитывает и не сохраняет. Экспорт не подтверждает актуальность установленного макроса, триггеров или protected ranges Google Sheets. Чтение Google Sheets не является атомарным снимком; перед будущим применением потребуется повторная проверка в режиме обслуживания.

Отчёт содержит структуру, число операций, категории, расположение архивных колонок/подписей, количество формул, диапазоны валидаций, число защит и конфликтные соответствия. Суммы, даты и комментарии операций, исходные формулы и credentials в отчёт не выводятся. Отчёт всё равно содержит личный справочник — хранить его локально, не публиковать без проверки.

`can_apply` всегда false: отсутствие найденных конфликтов не означает готовность к миграции. Расхождения подписи отчёта и критерия формулы не объединяются автоматически. Например, «Самокаты» и `Whoosh` могут обозначать разные записи; старое имя нужно явно сопоставить после решения владельца.

## Подтверждаемые соответствия

Внутренний API `migration_mapping.seed_legacy_taxonomy` подготавливает постоянные ID для первичной миграции. Они детерминированы ID таблицы и нормализованными исходными именами, поэтому повторная подготовка того же источника не назначает новые ID. Для уже мигрированной таблицы seeding запрещён по контракту: после переименования нужно использовать сохранённый реестр, а не строить его заново из названий.

`ReviewedMapping` содержит ID таблицы, отпечаток просмотренного источника, явное `confirmed=True` и список `LabelDecision` для точных адресов лист/ячейка. Каждая запись указывает целевые category_id/subcategory_id. `compile_label_index` возвращает индекс подписей текущего отчёта и старых архивов; суммы и сами листы не меняются. Изменение отпечатка, неверный контекст, неизвестный ID, лишняя ячейка или две архивные колонки с одним category_id отклоняются.

Если подпись аналитики совпадает с названием одной подкатегории, а формула считает другую, совпадение по тексту не заменяет решение владельца. Для старого снимка без формул известные подписи разрешаются только в контексте категории. Нераспознанные подписи требуют отдельных подтверждений; исходные операции не восстанавливаются из агрегатов.

Операторские команды применения находятся в `finance_bot.category_upgrade`. Конкретная карта для рабочей книги остаётся неподтверждённой.

## Порядок установки на копии

1. В Google Sheets создать тестовую копию книги и ещё одну неизменяемую резервную копию. Выдать сервисному аккаунту доступ к обеим. Сохранить установленный исходник Apps Script отдельно; `data/macros-v1.gs` — сохранённая локальная v1, но если установленный код отличается, нужен именно установленный исходник.
2. Выполнить preflight для тестовой копии. Рассмотреть найденные соответствия названий; без решения владельца по конфликтам нельзя применять план. Отчёты/планы/backup содержат личный справочник или операции, поэтому хранить в `secrets/category-migration/` (git-ignored), не в коммите.
3. Подготовить `mapping.json`: `source_fingerprint`, `spreadsheet_id` тестовой копии, `confirmed: true`, `decisions` с явными LabelDecision. Для выбора ID использовать `seed_legacy_taxonomy` на том же источнике и ID копии; не назначать их произвольно. Карта относится к точным адресам подписей и отпечатку источника, поэтому после изменений preflight повторяется.
4. Подготовить нативный план (чтение; код не создаёт копии автоматически):

```sh
python -m finance_bot.category_upgrade plan-native --target-id COPY_ID --credentials secrets/google-service-account.json --mapping secrets/category-migration/mapping.json --output secrets/category-migration/plan.json
```

5. Приостановить любые записи тестового бота и ручные правки тестовой копии. Выполнить установку, явно указав отдельную нативную резервную копию:

```sh
python -m finance_bot.category_upgrade install-copy --plan secrets/category-migration/plan.json --credentials secrets/google-service-account.json --backup-id BACKUP_COPY_ID --workspace secrets/category-migration/run --original-script secrets/category-migration/original.gs --maintenance-confirmed --confirm
```

Книга остаётся `applying/maintenance`. Повтор той же команды использует журнал шагов; другой план или изменённые исходные финансовые значения отклоняются. Защищаются служебные листы и ID, но владелец книги может обходить Google-защиты — во время обслуживания этого делать нельзя. Общей транзакции между Google UI, Python и Apps Script нет.

Если «Траты» оформлены как нативная Google-таблица с типами столбцов, установщик снимает тип только у B:C и их общие правила Dropdown: зависимые списки макроса задаются отдельно для каждой строки. Сама таблица, оформление, диапазон, значения и типы остальных столбцов сохраняются; исходные метаданные таблицы записываются в приватный журнал. Это устраняет ошибку Apps Script «В столбцах определенного типа это действие с ячейками запрещено». Сортировать по-прежнему только полные строки A:K; сортировка одной лишь старой нативной таблицы A:F не поддерживается.

6. В тестовой копии открыть **Расширения → Apps Script**, сохранить копию старого проекта и заменить исходник содержимым **`data/macros.gs`**. Не добавлять новый `saveMonthlyReport` рядом со старым: в проекте должна остаться одна реализация. Сохранить проект. В настройках проекта проверить часовой пояс таблицы; `fbRows` приводит даты к часовому поясу самой книги.
7. В редакторе Apps Script вручную запустить **`verifyFinanceBotMigration`**, предоставить требуемые разрешения Google для этой копии. Функция проверяет строки, создаёт выпадающие списки и печатает JSON-подтверждение в журнал выполнения. Сохранить этот JSON в `secrets/category-migration/script-proof.json`.
8. Проверить вычисленные ячейки и финализировать:

```sh
python -m finance_bot.category_upgrade finalize-copy --plan secrets/category-migration/plan.json --credentials secrets/google-service-account.json --script-proof secrets/category-migration/script-proof.json --confirm
```

Команда сравнивает пересчитанные в Sheets доходы, расходы, остаток, категории и подкатегории с независимым расчётом и сверяет неизменность источника. `ready/open` записывается последним. При ошибке формул, локали или исходных данных ready не публикуется.

Запись сгенерированных формул поддерживает проверенные локали `ru_RU` (разделитель аргументов `;`), `en_US` и `en_GB` (`,`). Иные локали требуют отдельной проверки совместимости; локаль книги автоматически не меняется.

9. `onEdit` — простой триггер в bound Apps Script. Он обрабатывает весь затронутый диапазон; отдельный таймер не требуется. Ручной запуск `refreshFinanceBotRows` выполняет полную сверку и обновляет списки на всех строках до `getMaxRows`, включая строки после 155. Служебные ID и справочники вручную не редактировать; сортировать целые строки A:K.
10. Для теста Telegram использовать отдельный тестовый токен и ID этой копии. Не запускать два polling-процесса с одним токеном. Проверить ручной ввод/правку/удаление, страницы аналитики, перенос и деактивацию внутренним сервисом, два закрытия месяца, отказы от очистки и замену архива. До этого проверки 4.3/5.3/6.3 не считаются выполненными.

## Локальная проверка и восстановление

Для офлайн-плана вместо `plan-native` доступна `plan --xlsx ... --target-id ... --mapping ... --output ...`. Такой план не устанавливается в Google-копию, если её нативный отпечаток отличается от экспорта; для установки нужен свежий `plan-native`.

```sh
python -m finance_bot.category_upgrade apply-local --plan secrets/category-migration/plan.json --workspace secrets/category-migration/local --original-script secrets/category-migration/original.gs --confirm
python -m finance_bot.category_upgrade restore-local --workspace secrets/category-migration/local --confirm
```

Результаты: `verified-copy.json`, неизменяемый `backup.json`, возобновляемый `state.json`, восстановленные `restored-copy.json` и `restored-script.gs`. Файлы содержат финансовые данные и создаются с правами 0600. Локальный snapshot не является XLSX и не заменяет нативную резервную копию со стилями, диаграммами и правами.

При нативном сбое оставить обслуживание включённым. До возобновления проверить журнал, исходные финансовые значения и резервную книгу. Для отката использовать нативную резервную копию и сохранённый исходник Apps Script, затем прежнюю версию бота. После появления новых операций простой откат запрещён: сначала сохранить и согласовать их перенос. Автоматическое восстановление поверх новых финансовых записей не выполняется.

## Закрытие месяца в v2

Сначала внести последнюю операцию, затем запустить `saveMonthlyReport`. Макрос сверяет строки и итоги, сохраняет сводку и снимок, предлагает замену существующего архива и отдельно спрашивает разрешение очистить траты. Отказ не очищает операции; ошибка оставляет обслуживание для проверки. Затем вручную изменить D1 (и D2 при смене года).

Архивные колонки сопоставляются по ID, новые добавляются справа. Удалённая категория остаётся: фактическая сумма в месяц деактивации, нули позже, старые суммы неизменны. Переименование меняет подписи, а перенос подкатегории не пересчитывает прошлую принадлежность. При операциях других месяцев очистка блокируется.

Это ещё не разрешение на миграцию рабочей книги или релиз новой версии; они выполняются отдельно после приёмки копии.
