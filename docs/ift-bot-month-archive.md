# Архивация месяца из ИФТ-бота

Функция предназначена только для ИФТ-книги `1jaEzmJPqYzxSp-HtDw-zwt_kPqSEs4enBrkG-Lc-UzA`. Промышленный бот, его таблица и установленный макрос не обновляются. До подключения web app и тестового выпуска новая кнопка ещё не появится.

## Однократная установка владельцем

1. В **ИФТ-таблице → Расширения → Apps Script** заменить существующий исходник полным содержимым `data/macros.gs`. Сохранить. Не создавать вторую реализацию saveMonthlyReport рядом со старой. Проверка ручных строк уже мигрированной книги — `refreshFinanceBotRows`.
2. В **Настройки проекта → Свойства скрипта** добавить три свойства из локального приватного файла `secrets/ift-month-archive/script-properties.json`: `FB_ARCHIVE_OWNER_ID`, `FB_ARCHIVE_SHEET_ID`, `FB_ARCHIVE_KEY`. Ключ предназначен только этому ИФТ endpoint и боту; не публиковать его и не присылать в чат.
3. **Развернуть → Новое развёртывание → Веб-приложение**: выполнять от своего имени, доступ «Все» (без браузерной сессии Google). Само действие защищено подписью HMAC; неподписанный запрос ничего не читает и не меняет. Авторизовать скрипт своим аккаунтом владельца ИФТ-книги. Скопировать URL, заканчивающийся `/exec`, и передать его для подключения ИФТ-бота. `/dev` не использовать.
4. После подключения и ИФТ-релиза отправить боту `/help`: появится «Архивация месяца». Команда `/archive_month` запускает тот же диалог. При следующем обновлении исходника web app нужно также обновить его deployment version через «Управление развёртываниями».

## Поведение кнопок

Бот показывает период из «Аналитика» D1/D2. «Сохранить архив» либо «Заменить архив» запускает существующий код Apps Script и проверяет результат. Только затем появляется отдельное предложение очистить траты и перейти к следующему месяцу. «Оставить траты» сохраняет архив, но не очищает операции и не переключает период.

Повтор старого подтверждения относится к старому request_id, а не к новому месяцу. Если HTTP-ответ потерян, «Проверить статус» запрашивает тот же журнал. При частичном сбое не отправлять новую архивацию и не открывать metadata вручную. Если безопасное завершение не доказано, нужен разбор сохранённого этапа.

Простой onEdit, ручной refreshFinanceBotRows и запуск saveMonthlyReport из таблицы используют общий ScriptLock с web app. Ручной пользователь Sheets и Python не разделяют этот lock: правки периода/операций между подтверждениями приводят к отказу от устаревшей очистки.

## Подключение стенда оператором

После получения URL в приватный `/opt/financebot/test/.env.test` добавляются:

```dotenv
MONTH_ARCHIVE_ENABLED=true
MONTH_ARCHIVE_URL=https://script.google.com/macros/s/DEPLOYMENT_ID/exec
MONTH_ARCHIVE_KEY=<ключ из ScriptProperties>
```

Передавать ключ через приватный JSON/stdin, не через аргументы команд. Файл остаётся 0600. `scripts/prepare_test_env.py` при передеплое сохраняет только эти проверенные ИФТ-настройки из существующего .env.test; endpoint/ключ из production не наследуются. Для отключения установить MONTH_ARCHIVE_ENABLED=false. Удалённый endpoint также нужно отключить либо сменить его ключ, если вызовы больше не нужны.

Если функция включена, рабочий шаг `finance_bot.release_check` до замены тестового контейнера проверяет подпись/версию endpoint через status с новым ID, не создавая архива. Неверные настройки, неподключённый макрос или несовместимый протокол блокируют замену; предыдущий ИФТ-контейнер остаётся работающим.

Обработка выполняется в Apps Script: Python не рассчитывает и не сохраняет архивные суммы. В ScriptProperties хранится компактный журнал этапов/отпечатков без исходных финансовых строк, на сервере — приватная ссылка request_id в `CATEGORY_CHANGE_STATE_DIR/month-archive/`. Эти данные не публикуются в Git.

## Приёмка на ИФТ

- Обновить `/help`, проверить кнопку и команду. Отмена первого подтверждения не создаёт архив и не очищает траты.
- Сохранить архив и выбрать «Оставить траты»: сводка и снимок созданы, траты и D1/D2 прежние.
- Повторить с существующим архивом: бот явно предлагает замену. Отказ от замены ничего не удаляет.
- Только по выбранному владельцем тестовому периоду подтвердить очистку: проверить сводку, читаемый снимок/диаграммы без служебных ID, очистку трат и переход месяца (декабрь → январь с новым годом).
- Нажать старую кнопку закрытого запроса: новый период не архивируется повторно. Новая трата между сохранением и очисткой должна блокировать старое подтверждение.
- После сетевого сбоя проверить статус того же запроса; не повторять неподтверждённую финансовую запись вслепую.

Эти проверки не закрывают приёмку production-архивации в конце месяца.
