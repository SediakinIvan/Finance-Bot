# Тестовый стенд

Рабочий бот использует ветку `main`, последний передеплой `v1.5.4` (стабильный код `v1.5.3`) и таблицу `1I6_HFCMVmxOD5buP6RdhtfJHld66tj7oMGArpW4AEC4`. Тестовый использует отдельный Telegram-токен и уже выделенную v2-копию `1jaEzmJPqYzxSp-HtDw-zwt_kPqSEs4enBrkG-Lc-UzA` с её существующим Apps Script. Новых копирований или миграций рабочей таблицы при раскатке теста нет.

- Ветка стенда: `feature/manage-categories`. Последний передеплой: `test-2026-11-12-2`, коммит `d85803a`.
- GitHub Actions: **Test stand**, push тега `test-*` на feature-коммите. `workflow_dispatch` объявлен, но после выделения стабильного main файл отсутствует в default branch; доступность ручного запуска в UI не гарантируется.
- Секрет репозитория: `TEST_TELEGRAM_BOT_TOKEN`. Не добавлять токен в Git или параметры workflow.
- Образ `test-<commit>`, Docker Compose project `financebot-test`, контейнер `financebot-test`.
- Каталог сервера: `<VPS_APP_DIR>/test`; `.env.test` приватный 0600; журнал `test/secrets/category-changes` отделён от рабочего.
- Общие SSH/registry-секреты берутся из существующего GitHub environment `production`. Это только доступ к серверу; команды работают с отдельным test-каталогом и Compose project.
- Google service account общий, ключ монтируется только для чтения. Таблица теста отдельная; финансовые данные рабочей таблицы в стенд не копируются.

Подготовка тестового env читает только основной Telegram ID и токен из серверного `.env`, чтобы сохранить владельца и исключить повторный polling рабочего бота. Рабочий файл не меняется. Дополнительные аккаунты в тесте выключены. Новый токен поступает через stdin из GitHub secret и не печатается.

Перед запуском проверяются v2/ready, доступ Google, доступность журнала и методы чтения справочника/статуса. Пайплайн `Test stand` не публикует `latest` и не выполняет рабочую раскатку. Теги `test-*` не совпадают с рабочим триггером `v*`.

Для проверки открыть нового бота, `/start`, `/version`, `/categories`. Разработку сначала проверять здесь; выпуск рабочего бота выполняется отдельно после приёмки. Успех CI означает раскатку контейнера, а живые сценарии всё равно требуют проверки.

Оба последних передеплоя прошли; 2026-11-12 владелец подтвердил, что оба бота работают и отвечают. Полная приёмка управления категориями не закрыта общим подтверждением доступности. Подробная [карта окружений](../openspec/context/09-environments-and-branches.md) и [спецификация выпуска](../openspec/specs/environments-and-delivery/spec.md) фиксируют текущие версии, источники конфигурации и ограничения.

Внимание: feature:compose.yaml содержит тестовый spreadsheet_id от предыдущей попытки v2-выпуска. Для настоящего теста используется compose.test.yaml. Продвижение одного Docker digest между окружениями пока не реализовано.
