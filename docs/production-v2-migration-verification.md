# Перенос v2 в production: состояние подготовки

## Подтверждено чтением

VPS: production-контейнер financebot использует образ коммита `77c4d221610d3d78d0ed70bfa03384aa4feda156`; financebot-test — `43cd94f24c51059a97ab65a5ca4db442a50c313b`. Контейнеры не останавливались и не пересоздавались.

Рабочая книга `1I6_HFCMVmxOD5buP6RdhtfJHld66tj7oMGArpW4AEC4` имеет legacy-структуру: 9 листов, 6 диаграмм, нет `_financebot_meta`. Эталон ИФТ `1jaEzmJPqYzxSp-HtDw-zwt_kPqSEs4enBrkG-Lc-UzA` имеет 17 листов, 7 диаграмм. Разница в числе диаграмм не является разрешением удалить/создать объекты без плана структурного переноса.

Полные нативные снимки, миграционные snapshots и preflight обеих книг сохранены в приватном git-ignored `secrets/production-migration/`, с SHA-256. Эти локальные снимки не заменяют отдельную нативную резервную копию и не являются доказательством остановки записей. В Google использован только scope spreadsheets.readonly; записи не выполнялись.

Preflight ПРОМ обнаружил старые расхождения: «Штрафы»/критерий «Штраф», «Самокаты»/критерий Whoosh и историческую подпись «Зал» в июньском архиве. Первые два соответствуют ранее обсуждавшимся решениям; перед установкой требуется точная карта по production-снимку без копирования UUID ИФТ. Исторические суммы не изменять.

## Блокирующие входные данные

Установленные bound Apps Script обеих книг пока не прочитаны: коннектор Sheets не предоставляет исходники скрипта, browser access host недоступен, нативное управление Chrome не разрешено. Нельзя считать локальный macros.gs резервной копией установленного исходника. Нужны фактические .gs файлы и сведения об установленных триггерах от владельца либо доступ к редактору. В текущем локальном макросе отдельно накоплены изменения UI, snapshot readback, chart rebind и переключения месяца.

У владельца запрошена готовность данных и окно без ручных/бот-записей. До ответа не начинать production-обслуживание или миграцию.

Задача 1.1 выполнена частично: прочитаны версии и структура, но не установленный Apps Script и полная эффективная production-конфигурация. Поэтому checkbox остаётся открытым. Остальные задачи не объявляются завершёнными. Боевые данные, формулы, макрос и runtime не изменены.

## Уточнение владельца и подготовленные планы

Владелец подтвердил: текущий исходник ПРОМ — `data/macros-v1.gs`, текущий исходник ИФТ — `data/macros.gs`; установку нового макроса в ПРОМ выполнит самостоятельно. Оба исходника сохранены приватно, SHA-256 записаны отдельно. Для v2 используются простой onEdit и onOpen; отдельный таймер макросом не требуется. Установку и проверку onEdit в ПРОМ ещё предстоит подтвердить.

Эффективная конфигурация VPS проверена чтением только разрешённых полей: ПРОМ v1.5.4, commit 77c4d22, рабочий spreadsheet_id; ИФТ test-test-2026-11-12-8, commit 43cd94f, собственный spreadsheet_id и журнал. Дополнительные аккаунты в обоих окружениях отключены. Токены не читались в вывод.

Подготовлены отдельные планы исходного ПРОМ и репетиционной копии с 13 точными решениями исторических подписей по ранее согласованным соответствиям: Штрафы/Штраф, транспортные Самокаты → Whoosh, архивное Зал → Спорт. Суммы и A:F не переписываются. Неактивный транспортный дубль остаётся в реестре, Зал сохраняется активной подкатегорией Спорт. UUID вычисляются для каждой целевой книги отдельно. План репетиции не используется как production-план.

Репетиционная копия создана: `1JFD28vzt5l6E7MDfQykfasUiAFy4G2AJL65KH4gToRI`. Исходная рабочая книга не менялась.

Миграционный установщик доработан: неизвестные пользовательские области аналитики/справочника сохраняются, коллизия нового блока с ними блокирует план, устаревшие ячейки известных блоков очищаются явно без clear всей аналитики. Существующие диаграммы мигрируются по диапазонам с сохранением ID, неоднозначность отклоняется, неизвестные диаграммы не удаляются. Для репетиции ещё нужны реальные проверки и восстановления; задача 2.1 пока остаётся открытой до завершения требуемых проверок.

24 целевых Python-теста миграции и Node core/archive прошли. Node проверил в том числе все 12 переходов месяцев и неизменность D2 в обычном месяце; это совместимость предоставленного владельцем макроса, не доказательство его установки в ПРОМ. Задачи 1.1, 1.2, 2.3 закрыты, production-миграция и выпуск не выполнялись.

## Текущий прогон реализации

Полный Python-набор: 224 теста прошли; Node core/archive прошли; strict OpenSpec — 12/12, diff --check чистый. Production Compose локально исправлен на рабочую книгу. В существующий CI/CD добавлен аргумент `--expected-spreadsheet-id` к release_check; неверная рабочая привязка отклоняется до Google-чтения и запуска polling. Эти изменения ещё не опубликованы и не развёрнуты.

Репетиционная установка на отдельную копию прошла с проверкой сохранности исходных финансовых значений и архивов; книга оставалась applying/maintenance. Промежуточный отказ Google на маске updateEmbeddedObjectPosition исправлен по [контракту Google](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/request#updateembeddedobjectpositionrequest): корень OverlayPosition подразумевается, используется маска `*`. Продолжение использовало тот же журнал и те же ID.

На копии выполнен пробный откат. Финансовые значения, формулы, исходные девять листов, шесть диаграмм с исходными ID/spec/position, типы нативной таблицы и свойства колонок совпали. Выявлено исчезновение двух исходных per-cell validation (B54/C54) при восстановлении typed table; проверяется порядок восстановления этих правил. До полной сверки задача 2.2 не закрывается и production-миграция не начинается.

## Прямое поручение на немедленный перенос

Владелец отменил дальнейшие репетиции и сообщил о собственных backup. Данные переносит после установки структуры, Apps Script устанавливает самостоятельно. Старый financebot остановлен; install_copy успешно установил структуру v2 в исходную production-книгу. Проверки против сумм ИФТ не выполняются. При завершении ready/open используется явный script_installation_deferred, не фиктивное доказательство установленного скрипта.
