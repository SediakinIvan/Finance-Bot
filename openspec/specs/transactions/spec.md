# Purpose
Текущий диалог по finance_bot/bot.py и tests/test_bot_data.py. Пользовательский инвариант: изменение финансовых записей требует подтверждения.

## Область действия

Этот основной контракт описывает стабильное поведение legacy/v1, принятое для рабочего main. Ссылки на Python/Apps Script относятся к **версии файлов в main**, а не к одноимённым файлам feature. Изменения v2 реализованы в feature/manage-categories и пока описываются её change-спецификациями. Сопоставление контрактов: [версии таблиц](../workbook-versions/spec.md); привязки и выпуски: [окружения](../environments-and-delivery/spec.md). Новые общие спецификации окружений не означают приёмку v2 в production.

## Requirements
### Requirement: Подготовка операции
Бот MUST собрать дату, тип, категорию, подкатегорию и положительную целую сумму в рублях до сохранения.
#### Scenario: Выбор даты
- **WHEN** пользователь выбирает сегодня или вчера
- **THEN** дата определяется в BOT_TIMEZONE (по умолчанию Europe/Moscow).
#### Scenario: Ручная дата
- **WHEN** пользователь вводит дату
- **THEN** принимаются ДД.ММ.ГГГГ и YYYY-MM-DD; сохраняется ДД.ММ.ГГГГ.
#### Scenario: Комментарий
- **WHEN** сумма введена
- **THEN** показывается предпросмотр с возможностью добавить необязательный комментарий длиной до 1000 символов.

### Requirement: Подтверждение и отмена
Бот MUST записывать операцию только после подтверждения предпросмотра.
#### Scenario: Отмена
- **WHEN** пользователь отменяет ввод или сохранение
- **THEN** данные этого диалога очищаются без записи в таблицу.
#### Scenario: Неопределённый результат записи
- **WHEN** адаптер сообщает ошибку сохранения
- **THEN** обработчик не повторяет сохранение, завершает диалог и просит проверить таблицу перед новой попыткой.

### Requirement: Подтверждение удаления
Бот MUST показать выбранную операцию и запросить подтверждение.
#### Scenario: Выбор для удаления
- **WHEN** пользователь открывает список
- **THEN** предлагаются последние десять операций, начиная с нижней строки листа.
#### Scenario: Устаревшее подтверждение удаления
- **WHEN** токен кнопки не совпадает с текущим токеном диалога
- **THEN** выбранная текущая операция не удаляется.

## Ограничения
- Состояние ввода хранится в памяти процесса; persistence в main.py не настроен.
- Токены текущего диалога есть у клавиатуры суммы и удаления. Кнопки сохранения имеют общий callback save:yes/save:no без токена; полную защиту старых кнопок сохранения эта реализация не гарантирует.
- Устойчивого идентификатора операции и гарантии exactly-once нет.
