# Design

## Context

В текущем `data/macros.gs` функция `saveMonthlyReport` проверяет архив, запрашивает подтверждение очистки, очищает операции и служебные снимки, затем выставляет `cleanExit=true` и просит вручную изменить D1. До этой ветки уже существуют выходы по отмене и проверки ошибок. Архивный снимок уже содержит исходные D1/D2. См. proposal.md.

## Goals / Non-Goals

**Goals:** добавить переход периода в самом конце успешной ветки, используя уже вычисленный `period`.

**Non-Goals:** любые прочие изменения макроса или бота; исправление старых ошибок, рефакторинг, изменение очистки, восстановление после сбоя, создание новых подтверждений или выпуск в пром. Предыдущие локальные исправления не переписывать и не включать в diff этой задачи.

## Decisions

1. Вставить запись следующего периода после существующей очистки служебных снимков, до `cleanExit=true`. Раннее переключение отвергнуто: оно изменило бы источник до заморозки архива или при отказе от очистки. Сохранение архива без очистки не считается полным закрытием месяца и не переключает период.
2. Вычислять следующий месяц из сохранённого `period`, без текущей даты и без повторного чтения уже изменённых ячеек. Для месяцев 1–11 писать только D1; для декабря записывать D1:D2 одним прямоугольным `setValues`, чтобы не делать две независимые записи года и месяца.
3. Только заменить текст уже существующего финального уведомления, убрав требование вручную изменить D1. Ни новые диалоги, ни новые служебные поля не нужны.

## Risks / Trade-offs

- [Сбой записи периода после очистки] → не выставлять cleanExit до успешной записи; сохранить существующее поведение maintenance. Не вводить отдельную систему восстановления или обещание транзакционности Sheets.
- [Случайная правка других частей] → проверить diff относительно текущего рабочего файла: разрешён только завершающий участок и целевые тесты. Фактические суммы и период архивного снимка проверяются регрессиями.

## Migration Plan

Схема книги не меняется. После отдельного apply предоставить владельцу минимальный заменяемый фрагмент `saveMonthlyReport` и точное место вставки для bound Apps Script ИФТ. Деплой Docker сам не устанавливает Apps Script. Откат этой функции — вернуть только фрагмент перехода и прежний текст уведомления. Рабочую книгу и main не обновлять.
