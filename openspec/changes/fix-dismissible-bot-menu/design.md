# Design

## Context

См. `proposal.md` для проблемы и `specs/bot-menu/spec.md` для поведения. Главное меню формируется в одном месте — `_main_menu_keyboard()` — и отправляется из `start_help()`, используемого для `/start` и `/help`. Сейчас выставлены `resize_keyboard=True` и `is_persistent=True`. Существующий тест прямо требует постоянного отображения.

Дизайн нужен для фиксации границы между настройкой Bot API и жестом клиента, а также обновления уже отправленной клавиатуры. Согласно [Telegram Bot API](https://core.telegram.org/bots/api#replykeyboardmarkup), `is_persistent=True` просит показывать меню при скрытии обычной клавиатуры; False позволяет скрывать и открывать меню иконкой. Бот не получает отдельного события смахивания клавиатуры.

## Goals / Non-Goals

**Goals:** устранить запрос принудительного отображения одним изменением конфигурации меню; сохранить доступность действий и определить проверку исходного жеста на устройстве.

**Non-Goals:** менять компоновку кнопок, внедрять inline-меню или команды скрытия, автоматически скрывать меню после каждого нажатия, менять финансовые диалоги, обновлять зависимости или выполнять деплой в рамках реализации.

## Decisions

1. Явно задать `is_persistent=False`, сохранив `resize_keyboard=True`. Это адресует обнаруженную настройку, совпадающую с симптомом. Удаление параметра дало бы аналогичное значение по умолчанию, но явное False лучше выражает контракт.
2. Не включать `one_time_keyboard`: оно добавляет автоскрытие после использования, которого пользователь не просил. Не применять `ReplyKeyboardRemove`, поскольку оно удаляет доступность клавиатуры через штатную иконку. Отдельный обработчик жеста не предусмотрен Bot API.
3. Сохранить подписи и ряды кнопок, авторизацию и обработчики. Переименовать существующий тест меню и заменить ожидание постоянного отображения проверкой отправленного сворачиваемого меню; оставить проверку всех кнопок. Проверить сериализованное значение `is_persistent=False` и сохранение `resize_keyboard=True`; не требовать конкретной формы сериализации отсутствующего `one_time_keyboard`, достаточно отсутствия True.
4. Обновить README: меню сворачивается средствами клиента, снова открывается иконкой или `/help`. В существующем чате требуется `/help`, чтобы клиент получил новую разметку.

## Risks / Trade-offs

- [Жесты и внешний вид зависят от клиента Telegram] → unit-тест подтверждает отправленный контракт; исходную последовательность проверить на телефоне пользователя после обновления меню. Не объявлять жест проверенным по результату unit-тестов.
- [В чате осталась старая клавиатура] → перед ручной проверкой отправить `/help`; автоматическая рассылка обновления не нужна.
- [Смена флага недостаточна на конкретной версии клиента] → записать ОС, версию Telegram и результат исходной последовательности; считать приёмку незавершённой, не расширять исправление до переработки меню без отдельного решения.

## Migration Plan

Изменить параметр, тест и README, выполнить `python -m unittest discover -s tests`. Выпуск выполнять отдельно по правилам проекта; данный план не разрешает деплой. После установки версии пользователь отправляет `/help`, проверяет скрытие обычной клавиатуры без появления меню, скрытие самого меню и повторное открытие иконкой. Обратная правка флага возвращает прежнее поведение и также требует обновления клавиатуры в чате; миграции данных нет.
