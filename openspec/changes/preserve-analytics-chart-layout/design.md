# Design

## Context

См. proposal.md. `report_blocks` автоматически включает категории с несколькими подкатегориями. `prepare_change` каждый раз генерирует «Аналитику» целиком, а native apply вызывает `apply_report_presentation`: она удаляет все существующие embedded charts и добавляет общую и диаграммы блоков. Поэтому добавление второй подкатегории может менять количество диаграмм. Старые тесты прямо ожидают delete/add, их контракт нужно заменить для обычного изменения справочника.

Основной spec workbook-versions сейчас обещает динамические блоки; delta меняет это правило на сохранение существующего dashboard. Прежние prepare-dynamic-categories артефакты остаются историей, а не разрешением добавлять диаграммы после этой доработки.

## Goals / Non-Goals

**Goals:** сохранить текущие объекты и оформление; добавлять расходную категорию в общую сводку и существующую большую диаграмму; оставить реестры, служебную детализацию и подтверждения работоспособными.

**Non-Goals:** перестройка шаблона, автоматическое удаление ранее созданных диаграмм, добавление новых видимых блоков, изменение архивной политики или очистка тестовых колонок, production. Количество не задаётся числом в коде: сохраняется фактический набор перед применением.

## Decisions

1. Разделить bootstrap представления и последующие операции справочника. Первоначальная установка не служит обработчиком каждого create/add/rename/move/deactivate. В штатном обновлении запрещены deleteEmbeddedObject/addChart; layout не восстанавливается по дефолтным ширинам и координатам. Повторная генерация всего листа отвергнута: уничтожает пользовательские правки и источники небольших диаграмм.
2. Для текущей «Аналитики» сохранять исходные ячейки/формулы вне общей сводки, D1:D2 и существующие блоки. Служебная `_financebot_detail` может расширяться по ID без видимого нового блока. При добавлении подкатегории существующие малые диаграммы продолжают читать прежние диапазоны: автоматически расширять их список строк в этой задаче не требуется.
3. Общую диаграмму находить по источнику данных сводки A9:B, а не по номеру в списке или одному лишь заголовку. Получать полную текущую spec и позицию, сохранять chart ID, менять только границы domain/series общей сводки. Для остальных charts запросов изменения нет. Отсутствие/неоднозначность — диагностируемый отказ до первого write.
4. Перед применением читать native metadata и проверять расположение новой строки: не перезаписывать занятые ячейки, не сдвигать блоки/якоря диаграмм. Выход за безопасную область требует отдельного изменения шаблона, а не скрытого перемещения объектов.
5. Снимок оформления/источников включать в проверяемый приватный план представления; непосредственно перед первой записью перепроверять его актуальность. Старый неподтверждённый preview требует новой подготовки. Для уже pending-запроса нельзя подменять сохранённый план новым; при несовместимости требуется явное восстановление.
6. Применение остаётся идемпотентным по request_id. Подтверждение, source/revision gates и проверки финансовых сумм сохраняются; отсутствие новых charts проверяется readback native metadata. Повтор/resume не создаёт новую сводную строку.

## Risks / Trade-offs

- [Пользовательские диаграммы нестандартного типа/источника] → без однозначного распознавания общей диаграммы отказ до write; не угадывать ID по порядку.
- [Данные новой подкатегории не появляются отдельной строкой существующего малого графика] → это следствие запрета автоматически расширять видимую детализацию; её суммы входят в общую категорию, служебный detail остаётся полным.
- [Строка сводки пересекает объект] → предварительная проверка свободного места и отказ, вместо автоматического сдвига.
- [Общий helper используется миграцией] → сохранить отдельный bootstrap путь и тесты первичной установки; category mutation не должна вызывать его.
- [Есть незакоммиченные исправления месячного макроса] → сохранить их, но не смешивать с реализацией chart change и не объявлять этот propose их выпуском.

## Migration Plan

Новая схема финансовых строк и миграция книги не нужны. До ИФТ-проверки сохранить native chart metadata и контрольные ячейки dashboard; после create/add сравнить количество, ID, позиции, spec и единственное разрешённое изменение main-chart range. Проверить архивный снимок без очистки операций. Исходник bound Apps Script этой задачей не обновляется. Только после отдельного apply и тестов — test-тег и ИФТ-приёмка; main/пром не изменять.

## Вопрос об архивных колонках вне scope

Физические колонки возвращаются из `_financebot_archive_columns` и списка всех расходных категорий. Стабильное соответствие ID↔колонка и нули после деактивации обеспечивают сохранение истории. Для неиспользованных неактивных категорий возможно отдельное исключение, но решение владельца ещё не получено. Этот change не удаляет колонки, не перенумеровывает индекс и не разрешает ручное удаление связанных данных.
