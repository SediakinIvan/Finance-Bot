# Spec Delta

## ADDED Requirements

### Requirement: Исторический индекс не блокирует несвязанные изменения
Создание категории/подкатегории, перенос и деактивация MUST не требовать существования старого снимка, подписи которого не меняются этими действиями. Такие изменения SHALL сохранять исторические записи индекса без автоматического удаления и не создавать отсутствующие архивы.

#### Scenario: Новая категория после удаления старого снимка вручную
- **WHEN** у ИФТ-книги есть запись индекса для отсутствующего архивного листа и пользователь вводит новую категорию с допустимыми подкатегориями
- **THEN** бот показывает предпросмотр; до подтверждения нет записи в Sheets, после подтверждения категория применяется без создания или очистки старых архивов.

#### Scenario: Переименование при отсутствующем снимке
- **WHEN** глобальное переименование требует индексированного архива, которого нет
- **THEN** изменение отклоняется с объяснением отсутствия архивного листа; суммы, старые подписи, метаданные и индекс не исправляются по догадке.

### Requirement: Наблюдаемый исход создания категории
Ввод подкатегорий SHALL приводить к предпросмотру либо видимой ошибке с возможностью повторного ввода. Диалог MUST не закрываться без явной отмены или перехода в другой сценарий. Закрытие SHALL сохранять в истории сообщения об ошибке, предпросмотре и успешном применении.

#### Scenario: Список подкатегорий
- **WHEN** введены «Белье», «Верхняя одежда», «Одежда», «Аксессуары» отдельными строками
- **THEN** в предпросмотре показаны категория и все четыре подкатегории; действие не выполняется до подтверждения.

#### Scenario: Ошибка подготовки
- **WHEN** подготовка плана возвращает ошибку
- **THEN** бот объясняет ошибку и сохраняет черновик для исправления; последующая отмена не заменяет текст ошибки общим «закрыто».

#### Scenario: Подтверждение и закрытие
- **WHEN** пользователь подтверждает применённое создание и затем закрывает меню
- **THEN** факт успеха остаётся в переписке, повтор старого подтверждения не создаёт дубль.

### Requirement: Исправление выпускается только на ИФТ
Исправление MUST разворачиваться из feature/manage-categories существующим Test stand workflow по test-тегу. Main, v-теги, production Compose/env, рабочий контейнер и рабочая таблица SHALL оставаться без изменения.

#### Scenario: Успешные проверки
- **WHEN** регрессионные, полные Python/Node и OpenSpec-проверки пройдены
- **THEN** допускается автоматический test deploy; рабочий deploy не запускается, финансовые данные в обеих книгах не создаются для проверки без подтверждения владельца.
