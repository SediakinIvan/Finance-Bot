# Design

## Context

См. proposal.md. На настоящем снимке ИФТ-книги read-only probe подтвердил отсутствие категории «Одежда» и ValueError в цикле архивных подписей prepare_change. Цикл исполняется для всех действий, хотя старые имена меняет только rename. Удалять устаревшие ссылки из книги или восстанавливать пропавший архив не разрешено. Текущие UI-тесты вызывают callbacks напрямую и не проверяют сохранение текста сообщения при закрытии.

## Goals / Non-Goals

**Goals:** корректный create preview на существующей ИФТ-книге; сохранение строгого rename и истории; объяснимый результат UI; доказательная регрессия и test-only выпуск.

**Non-Goals:** чистка архивного индекса, исправление архивов/сумм, миграция, Apps Script, production, переработка всего диалога.

## Decisions

1. Обход исторических подписей выполняется только при rename. В иных действиях записи индекса архивов остаются как были; индекс текущей аналитики регенерируется обычным путём. Добавление/перенос/деактивация не меняют исторические имена. Сохраняем полный source fingerprint, revision и подтверждение. Альтернатива пропускать отсутствующие архивы при rename отвергнута: скрыла бы неполное глобальное переименование.
2. Ошибку отсутствующего архива при rename преобразуем в понятное сообщение уровня category management. Финансовый снимок и сырые API-ответы в сообщения/логи не выводим.
3. Закрытие callback удаляет только inline-клавиатуру и отправляет отдельное сообщение о завершении/отмене, сохраняя текст исходной ошибки/успеха. У неподтверждённого черновика явная отмена; у pending закрытие не объявляется откатом; после complete phase не остаётся preview.
4. Дополнить модельные тесты dangling-индексом и UI-тесты настоящим ConversationHandler/Update с подменённым Bot API. Сетевые методы записи Sheets в автоматических тестах не вызываются. Отдельно повторить read-only prepare_change на реальном снимке ИФТ, не применять план.

## Risks / Trade-offs

- [В индексе остаются устаревшие ссылки] → это сознательно сохранённое состояние источника, не разрешение на неполный rename; отдельная очистка требует решения владельца.
- [UI-исправление не объясняет весь пользовательский transcript] → подтверждённый backend-отказ покрывается live snapshot, а последовательность переходов и отсутствие самопроизвольной отмены проверяются через маршрутизацию.
- [Ошибочный рабочий выпуск] → commit/push только feature и test-тег; main и production файлы не изменять, проверить origin/main до/после.

## Migration Plan

Миграция не требуется. После тестов выпустить test-тег через Test stand, дождаться успеха, сообщить тестовую версию владельцу. При сбое теста оставить промышленный процесс как есть; откат test на предыдущий test-тег выполнять отдельным test deploy, не менять таблицу и не удалять журналы. Полная живая приёмка пользователем — после выпуска.
