# Design

## Context

См. proposal.md. Сейчас saveMonthlyReport в data/macros.gs получает активную книгу, вызывает getUi и дважды спрашивает согласие через alert. Он считает и проверяет итоги, пишет сводку/снимок, затем очищает операции и переключает D1/D2. Имеются Node-тесты успешного закрытия, отказов, дублей, смешанных периодов, диаграмм и всех 12 переходов месяца. Python-клиент уже читает таблицу через service account, но не умеет запускать bound Apps Script.

Текущее меню имеет 11 кнопок, включая «Категории»; распознавание кнопок участвует в фильтрах ввода транзакции. prepare_test_env.py пересоздаёт .env.test, поэтому новые настройки нужно явно проводить через него/существующий Test stand workflow. Сам deploy контейнера не обновляет Apps Script.

ПРОМ уже на v2.0.0, но приёмка реальной production-архивации в конце месяца остаётся открытой по решению владельца. Новая функция предназначена только для ИФТ и не закрывает эту приёмку.

## Goals / Non-Goals

**Goals:** управлять существующим архиватором из Telegram; сохранить проверки и два этапа согласия; показывать достоверный статус после сетевого сбоя; исключить запуск на ПРОМ.

**Non-Goals:** новый Python-архиватор, изменение формул/категорий/архивной политики, автоматическое расписание, production-перенос и новый механизм полного rollback книги.

## Decisions

### 1. Тонкая оболочка над общим ядром макроса

Выделить из saveMonthlyReport существующие операции подготовки, сохранения/проверки архива и подтверждённой очистки/смены периода. Sheets-оболочка сохраняет прежние окна; web-оболочка принимает подтверждения из Telegram. Расчёты fbArchiveValues, snapshotView, реестры колонок/подписей и условия отказа переиспользуются. Прямой вызов существующего saveMonthlyReport невозможен из-за UI-контекста; эмуляция интерфейса и переписывание логики на Python отвергнуты.

HTTP-вход открывает фиксированную книгу через openById, не getActiveSpreadsheet. Для web app getDocumentLock возвращает null, поэтому общие изменяющие входы установленного ИФТ-проекта используют один ScriptLock; lock освобождается до ожидания человеческого ответа и заново берётся с проверкой источника. Python и ручной пользователь Sheets не участвуют в этом lock: остаются metadata maintenance и повторная проверка source fingerprint.

### 2. Подписанный Apps Script web app

Использовать doPost/ContentService JSON в bound-проекте ИФТ, исполняемом владельцем. scripts.run отвергнут: Google явно не поддерживает его с нынешним service account; ввод отдельной OAuth-сессии владельца сложнее нужной задачи. Web app допускает HTTP-доступ без браузерной Google-сессии, но действия приложения доступны только после проверки HMAC-SHA256.

В ScriptProperties хранятся случайный общий ключ, разрешённые owner ID и фиксированный ИФТ spreadsheet_id. В ИФТ env — URL /exec и такой же ключ; production не получает эти настройки. Запрос содержит подписанную строку payload с action, request_id, owner_id, spreadsheet_id, timestamp, nonce и параметрами этапа. Подписываются точные UTF-8 байты payload, срок допуска — 5 минут. Неподписанные/просроченные запросы отвергаются до openById; nonce не позволяет повторить другой эффект, одинаковый request_id возвращает сохранённый этап. Разрешён только закрытый набор действий preview/archive/clear/status/cancel, произвольного вызова функций нет.

Приватный endpoint не становится универсальным доступом к Drive/Sheets владельца: проверяется фиксированная ИФТ-область, переданный другой ID отвергается. Ключи передаются в test provisioner через JSON stdin и сохраняются в приватном .env.test, не в URL, аргументах и логах. POST-ответ ContentService может перенаправляться на script.googleusercontent.com; клиент принимает только ожидаемые HTTPS Google-hosts, не пересылая подпись на произвольный redirect.

### 3. Два подтверждения, один сохраняемый запрос

Кнопка/команда создаёт preview без финансовых записей: период D1/D2, наличие архива, source digest, revision. Подтверждение «Сохранить» либо «Заменить архив за …» вызывает этап archive. Общий код сохраняет и проверяет сводку/снимок; только после этого бот предлагает «Очистить траты и перейти к следующему месяцу» и «Оставить траты».

При отказе архив остаётся, траты и период прежние, metadata возвращается в open по прежним правилам. Между сохранением и подтверждением очистки lock не удерживается, книга может оставаться open: новая трата инвалидирует старое разрешение на очистку. Перед clear заново проверяются операции, период, revision и сохранённый архив; при изменении нужно повторно сохранить актуальный отчёт, ничего не удаляя по старой кнопке.

В ScriptProperties хранится компактный журнал ID/owner/scope/периода, digest, этапа и результата, без финансовых строк. Число сохранённых записей ограничено; единственный незавершённый запрос не вытесняется. Локальный приватный журнал бота хранит тот же ID, чтобы после рестарта запрашивать status, а не создавать новый запрос. Для идущего шага повтор возвращает running; завершённый шаг возвращает прежний результат. Старый ID после переключения месяца не читает новый период как новую цель.

Перед необратимыми шагами сохраняются checkpoints, после — readback. Если execution оборвался между очисткой и переключением периода, продолжение подтверждает фактическое состояние того же запроса и выполняет только недостающий этап. Если это нельзя доказать, статус recovery_required и maintenance сохраняются; не угадывать и не обещать автоматический rollback. Эти состояния не подменяют журнал управления категориями и его pending_request_id.

### 4. Telegram и изоляция выпуска

Отдельный диалог с inline-подтверждениями; каждый message/callback проверяет владельца и личный чат. Кнопка добавляется последним рядом при enabled test-конфигурации; фильтры ввода не трактуют её текст как сумму/примечание. /help обновляет старую reply-клавиатуру. Без включения функция не показывается и команда не выполняется.

Клиент показывает «выполняется», проверенный результат либо сохранённый незавершённый статус. При timeout не повторяет archive/clear как новую запись: сначала status с тем же request_id. Не держит event loop заблокированным синхронным HTTP-вызовом. Совместимость endpoint проверяется чтением статуса/версии без архивации; отсутствие подключения не выдаётся за завершённую фичу.

Реализация и test-тег — в feature/manage-categories на актуальной принятой основе; main, v-теги, production Compose/endpoint и установленный production Script не меняются. Установка обновлённого data/macros.gs и развёртывание web app выполняются только в ИФТ-проекте. Отдельная инструкция владельцу обязательна: он уже устанавливает макросы самостоятельно.

## Risks / Trade-offs

- [Web app исполняется с правами владельца] → HMAC до доступа к книге, фиксированная область и набор действий, свежесть/повторы запросов, секреты только в приватной конфигурации. При отключении функции endpoint также выключается либо ключ ротируется владельцем.
- [Нет UI и document lock в удалённом контексте] → explicit openById, общий ScriptLock, отсутствие UI-вызовов в ядре; прежняя ручная оболочка покрывается регрессией.
- [Google timeout или потеря ответа после удаления] → долговечный request_id/checkpoints, status и проверка фактического результата, никакой слепой повторной очистки.
- [Ручное изменение между подтверждениями] → исходный fingerprint/revision/period сверяются перед записью; при конфликте сохраняются операции.
- [Владелец не обновил deployment version после установки исходника] → проверка версии протокола; инструкции Deploy → Manage deployments с новым version и /exec, не /dev.

## Migration Plan

1. Выделить общее ядро и Node-регрессией сохранить поведение ручного макроса. Добавить подписанный web adapter и журнал, проверить UI-less вызовы и частичные сбои.
2. Добавить клиент/диалог и test-only конфигурацию; Python-тестами проверить подтверждения, изоляцию и повторы. Записать короткую инструкцию подключения.
3. Владелец обновляет только ИФТ Apps Script, задаёт свойства и развёртывает web app. Настроить приватные ИФТ URL/ключ и проверить соединение без записи.
4. Выпустить ИФТ существующим test-пайплайном; владелец проверяет отмену, замену архива, отказ/согласие очистки и потерю ответа. Архивацию/очистку финансовых данных для приёмки выполнять только по его явному подтверждению.
5. Для отката функции отключить её ИФТ-флаг и endpoint; незавершённый запрос сначала довести до доказанного состояния. Отключение не восстанавливает уже очищенные траты и не объявляется rollback финансов.

## Источники ограничений Google

- https://developers.google.com/apps-script/api/how-tos/execute — scripts.run не поддерживает service accounts.
- https://developers.google.com/apps-script/guides/web — doPost и execute as owner.
- https://developers.google.com/apps-script/guides/bound — active-document методы недоступны при web app/API execution.
- https://developers.google.com/apps-script/reference/lock/lock-service — getDocumentLock вне document-контекста возвращает null.
- https://developers.google.com/apps-script/guides/content — перенаправление ContentService на script.googleusercontent.com.
