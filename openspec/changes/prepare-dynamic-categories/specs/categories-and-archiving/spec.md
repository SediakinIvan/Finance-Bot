# Spec Delta

## MODIFIED Requirements

### Requirement: Загрузка категорий
Бот MUST загружать актуальные варианты по постоянным ID из единого справочника пользовательской таблицы при начале нового ввода.
#### Scenario: Разбор справочника
- **WHEN** читается справочник новой версии
- **THEN** связи определяются по ID; предлагаются только активные категории и активные подкатегории с текущей принадлежностью; неоднозначные или повреждённые связи отклоняются.
#### Scenario: Доход
- **WHEN** тип распознан как доход
- **THEN** категория отображается как «Доход», подкатегория означает источник дохода; их связи также имеют постоянные ID.
#### Scenario: Нет пригодных вариантов
- **WHEN** обязательные поля отсутствуют или нет пригодных строк
- **THEN** начало ввода завершается с сообщением об ошибке.
#### Scenario: Единственная подкатегория
- **WHEN** для выбранной категории или дохода доступна одна подкатегория
- **THEN** она выбирается автоматически.
#### Scenario: Изменение во время ввода
- **WHEN** перед подтверждением обнаружена смена версии справочника, затрагивающая выбранную пару
- **THEN** устаревший выбор не сохраняется автоматически; пользователь должен проверить актуальные варианты и подтвердить операцию заново.

## ADDED Requirements

### Requirement: Динамические архивные категории
Сводный архив MUST определять колонки категорий по идентичности справочника, сохраняя уже существующие колонки и прошлые значения.
#### Scenario: Новая категория
- **WHEN** появилась новая категория расходов
- **THEN** её колонка доступна при следующей архивации без правки исходного текста макроса; существующие колонки и суммы не сдвигаются по смыслу.
#### Scenario: Удаление в текущем месяце
- **WHEN** категория деактивирована в месяце M
- **THEN** при архивации M записывается фактическая сумма операций этой категории, а для периодов после M записывается ноль; прежние месяцы неизменны.
#### Scenario: Переименование
- **WHEN** категория переименована
- **THEN** её существующая колонка и подписи месячных снимков обновляются без создания дублирующей колонки и без изменения сохранённых сумм.
#### Scenario: Перенос подкатегории
- **WHEN** архивируется месяц, содержащий операции до и после переноса
- **THEN** суммы распределяются по категориям каждой операции, а не по текущей принадлежности подкатегории.

### Requirement: Проверяемое закрытие месяца
Архивация MUST сохранять сводку и снимок аналитики до очистки и MUST требовать явного подтверждения очистки финансовых записей.
#### Scenario: Ошибка или отказ
- **WHEN** снимок не создан, итоги не сверены, обнаружены некорректные связи либо пользователь отказался от необходимой замены архива
- **THEN** «Траты» не очищается и успех архивации не объявляется.
#### Scenario: Повторная архивация
- **WHEN** пользователь повторяет закрытие того же периода
- **THEN** повтор не создаёт дублирующую сводку; замена существующих данных требует подтверждения.
#### Scenario: Операции других периодов
- **WHEN** «Траты» содержит операции вне закрываемого месяца
- **THEN** очистка не выполняется; пользователь получает сообщение о конфликте периода до удаления данных.
