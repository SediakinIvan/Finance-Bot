# Spec Delta

## MODIFIED Requirements

### Requirement: Формат финансовой записи
Адаптер MUST сохранять пользовательские поля Дата, Категория, Подкатегория, Сумма, Доход/Расход, Примечание в прежнем порядке и постоянные ID операции, категории и подкатегории в служебных полях.
#### Scenario: Подтверждённая запись
- **WHEN** бот сохраняет подтверждённую операцию
- **THEN** дата записывается текстом ДД.ММ.ГГГГ, сумма — положительным целым числом рублей, пользовательские значения передаются с RAW, а ID сохраняются в той же операции записи.
#### Scenario: Фиксация категории операции
- **WHEN** создаётся операция
- **THEN** сохраняется выбранная категория; её ID не вычисляется впоследствии из текущего родителя подкатегории.

### Requirement: Последние операции и удаление
Адаптер MUST читать строки с непустой датой и перед удалением сверять ID и снимок выбранной операции.
#### Scenario: Последние десять
- **WHEN** запрошены последние операции
- **THEN** возвращаются последние десять заполненных строк в порядке листа, без сортировки по дате операции.
#### Scenario: Строка изменилась
- **WHEN** ID или пользовательские поля не совпадают со снимком выбранной операции
- **THEN** удаление отклоняется.
#### Scenario: Снимок совпал
- **WHEN** пользователь подтвердил удаление и снимок совпал
- **THEN** удаляется физическая строка целиком, нижние строки сдвигаются; сортировка перед подтверждением не приводит к удалению другой операции.

## ADDED Requirements

### Requirement: Ручная работа с операциями
Пользователь MUST сохранять возможность добавлять, редактировать и удалять операции в Sheets; доступные категории и подкатегории MUST выбираться из списков единого справочника, а ID поддерживаться автоматически.
#### Scenario: Новый ручной ввод
- **WHEN** пользователь выбирает допустимую активную пару в новой строке
- **THEN** ей присваиваются ID операции, категории и подкатегории без ручного ввода ID.
#### Scenario: Редактирование выбора
- **WHEN** пользователь меняет категорию или подкатегорию существующей операции на допустимую пару
- **THEN** её ID обновляются согласованно; прежний ID не остаётся незаметно связанным с новым названием.
#### Scenario: Вставка диапазона или неверная пара
- **WHEN** вставлены несколько строк либо неоднозначные или несовместимые значения
- **THEN** все затронутые строки проверяются; ошибочные строки видимо отмечаются и блокируют подтверждение итогов и архивацию до исправления.
#### Scenario: Исправление других полей
- **WHEN** меняется сумма, дата или комментарий исторической операции
- **THEN** её сохранённые связи не заменяются текущей принадлежностью подкатегории.
#### Scenario: Расширение таблицы
- **WHEN** операции добавлены за пределами ранее подготовленного диапазона
- **THEN** поддерживаемый ввод получает валидации и обработку ID, без постоянного ограничения строками 2:155.

### Requirement: Проверяемая миграция
Миграция MUST предоставлять предварительный отчёт, сохранять исходные данные и сверять связи и финансовые итоги до включения новой схемы.
#### Scenario: Неоднозначная история
- **WHEN** названия не позволяют однозначно восстановить ID, включая несовпадения Самокаты/Whoosh и архивные подписи
- **THEN** миграция выдаёт список конфликтов и требует подтверждённого соответствия вместо автоматического объединения.
#### Scenario: Архив без исходных операций
- **WHEN** доступны только сводка и снимок старого месяца
- **THEN** сохранённые значения и подписи связываются со справочником без выдумывания построчной истории.
#### Scenario: Повторный запуск или сбой
- **WHEN** миграция запускается повторно после ошибки
- **THEN** уже назначенные ID не меняются; непроверенная схема не объявляется готовой, восстановление возможно из сохранённой копии.
#### Scenario: Несовместимая версия
- **WHEN** новая версия бота обращается к немигрированной или незавершённой таблице
- **THEN** запись блокируется с объяснением необходимости завершить миграцию; операции не смешивают две схемы.
