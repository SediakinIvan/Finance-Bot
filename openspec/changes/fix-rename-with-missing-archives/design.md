# Design

## Context

В `prepare_change`, ветка rename, цикл по `_financebot_archive_labels` проверяет наличие каждого листа до обработки подписи и выбрасывает `An indexed archive sheet is missing`. `CategoryManager` переводит её в сообщение владельца. Тест `test_rename_still_refuses_missing_archive_before_mutation` закрепляет этот отказ. Create/add/move/deactivate уже игнорируют несвязанные отсутствующие снимки. См. proposal.md.

## Goals / Non-Goals

**Goals:** убрать глобальную блокировку rename из-за отсутствующего необязательного снимка и сохранить достоверность подтверждения.

**Non-Goals:** очистка индекса, восстановление или переименование листов, правка финансовых значений, макроса и диаграмм, миграция, изменение main/прома.

## Decisions

1. Перед обработкой подписи разрешить пропуск отсутствующего листа только для месячных снимков с принятой оболочкой имени `Архив (…)`. Произвольный отсутствующий лист, обязательная сводка и служебные листы остаются ошибкой. Не перехватывать ошибки Google как отсутствие листа: отсутствие определяется по успешно прочитанному полному снимку книги.
2. Ссылки на пропущенные снимки оставить в `_financebot_archive_labels`. Автоочистка отвергнута: владелец может вернуть лист из резервной копии; переименование не разрешает удаление служебной истории. Обрабатывать все существующие индексированные подписи как раньше, включая архивные колонки, заголовки и подписи перенесённых подкатегорий.
3. Список уникальных пропусков формировать при подготовке точного плана и передавать в текст предпросмотра. Сохранять предупреждение вместе с request.json, а не пересчитывать обещания после подтверждения. Глобальные source fingerprint/revision/UUID и порядок native apply остаются прежними. Отдельная смена версии старых журналов не требуется: старый незавершённый план не перепланировать автоматически.
4. Заменить тест глобального отказа на матрицу успешных rename категории/подкатегории и активности; дополнить отрицательными случаями обязательных листов и повреждений. Native-тест должен подтвердить неизменные суммы и индекс, отсутствие создания отсутствующего снимка и идемпотентное resume.

## Risks / Trade-offs

- [Пропуск принят за восстановление истории] → явное предупреждение до подтверждения; восстановление архивов отдельная работа владельца.
- [Скрытие реального повреждения книги] → узкая проверка имени необязательного снимка; прочие ошибки и проверки ID/формул сохраняются.
- [Восстановление листа между preview и apply] → исходный fingerprint меняется, требуется новый подтверждённый план.

## Migration Plan

Схема книги прежняя. Реализация отдельно по apply, тестирование и выпуск только ИФТ существующим test-пайплайном. Накопленные локальные правки месячного макроса не включать в бот-фикс. Откат к предыдущему тестовому образу возвращает прежнюю блокировку rename, но не отменяет уже подтверждённые имена. Журналы незавершённых операций сохранять.
